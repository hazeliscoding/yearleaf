# Roadmap

Derived from the accepted architecture record
([docs/Infinite-Desk-Calendar-Architecture-Decisions.md](docs/Infinite-Desk-Calendar-Architecture-Decisions.md)),
whose delivery order this tracks. Checked items are done; the rest are in
planned order. Version 1 is a fully offline, single-user desktop
application — no accounts, no cloud, no sync.

## Milestone 0 — Repository foundation ✅

- [x] pnpm workspace: `apps/desktop`, `packages/{domain,canvas,deskbound,persistence}`
- [x] Angular 22 application scaffold (signals, zoneless, Vitest)
- [x] Deskbound design system ported from the design reference (tokens + Angular components)
- [x] Architecture record and design reference committed under `docs/`

## Milestone 1 — The spatial screen ✅

- [x] Deterministic date↔world mapping (`@infinite-desk/canvas`, epoch 2020-01-01, 320 units/day) with tests
- [x] Viewport math: focal-point-preserving zoom, pan, zoom-tier thresholds, with tests
- [x] Application shell: toolbar, tool rail, contextual inspector, ⌘K command palette, universal search overlay
- [x] Year / month / week / day tier sheets on a pannable, zoomable canvas (DOM-rendered)
- [x] Desk objects: sticky notes, images, files, freeform text; drag with transient state
- [x] Command architecture and universal undo/redo (add, move, delete, payload edit)
- [x] Light and dark themes; reduced-motion tokens

## Milestone 2 — PixiJS workspace ✅ (delivery steps 2–4)

The workspace is now one continuous world rendered by PixiJS 8
(design record: [docs/design-canvas-renderer.md](docs/design-canvas-renderer.md)):
months live in fixed world positions (3×4 year blocks), the detail tier
derives from the zoom level, and month navigation is panning.

- [x] PixiJS 8 scene with explicit layers (Calendar, Event, Note, Drawing, Attachment, Connector, Interaction)
- [x] Calendar grid rendered from the shared date↔world mapping with progressive detail per zoom tier
- [x] Viewport culling (visible-month arithmetic) and a spatial index for hit testing
- [x] Selection, movement, resizing (SE handle), delete, and arrow-key nudging against the Pixi scene
- [x] DOM overlay editing for text objects **and sticky notes** (canvas-positioned editor)
- [x] Real month navigation across all of time (tier presets, focused-month labels, date jumps)

Deferred out of this milestone (tracked in the design record): drawing and
connector content, bespoke week/day hour-ruler layouts, rotation handle,
multi-select, and sharper text rasterization at high zoom.

## Milestone 3 — Desktop shell and persistence (delivery steps 1 & 5)

The navigator now names the month filling the screen rather than the one under the centre point, which is how it came to report "July 2026" while October and November were on screen. And the wheel zoom factor was linear in the wheel delta, so a notch of 120 asked for a scale of -0.2 and clamped: three notches out from any zoom landed on a view of several blank years
- [x] The scroll trap is closed on the canvas, where the deceiving happens. A sheet whose own title has scrolled off the top keeps naming itself in a band pinned to the top of the viewport, with the weekday letters aligned to the columns they name — which is the other half of the misreading, since the reader who got lost concluded the columns themselves were wrong. The band names the sheet that is *unlabelled*, not the one filling the screen: drifting down from September puts September's last rows along the top and December's sheet, header and all, below them, and December above September is exactly the surprise. So the moment a drag crosses a quarter now announces itself. The band stays out of a whole-year view where every sheet is titled, off bare desk where there is nothing to name, and off a sliver of the month above that the default framing leaves showing over the gutter
- [x] The gutters are signposted. A seam states the distance it spans rather than naming the sheet across it — the count of bars *is* the distance, three across a horizontal gutter and one down a vertical one, undirected so neighbouring seams cannot contradict each other and the mark stays true read upward. `3 MONTHS` is set once along each seam, `1 MONTH` along each side gutter, and at a row's end a catchword names the month the sequence continues on, marked with a stroke that drops a row and runs back to the start of it. The reader who had been caught three times confirmed the distance label works — "someone finally put a sign on the trapdoor" — and would now scroll freely
- [ ] Gutter leftovers the 2026-09-18 finish gate left open after measuring: `3 MONTHS` is set *on* the middle bar, so the stack resolves as rule-caption-rule and the three rules and the words are never seen uninterrupted together — declined for now because the caption occupies about 155 of a 2192-unit span, so the triple rule is uninterrupted either side of it, but the gate is right that nothing prompts counting; and the legend was cut from two copies to one on the reader's "repeated text reads as texture" verdict, which loses the redundancy that kept one copy clear of the zoom widget and can be panned off screen entirely at the week tier. Also unguarded: a seam clipped at the viewport edge shows fewer bars than it means, though a partly-shown horizontal stack cannot be misread as the vertical one-month mark
- [ ] Gutter leftovers from that same pass: the catchword only prints in the rightmost column, so eight months in twelve never see a month name in a gutter, and it is pinned to the sheet's right edge so it is off-screen at the zoom people actually work at; the marks are inert paint, where clicking "October" ought to fly you there; nothing announces a crossing as it happens, which would land harder than a permanent label; and the marks vanish between 38% and 32% zoom with nothing to say they have gone
- [ ] Scroll-trap leftovers: the gutters between sheets are still blank texture, so a reader mid-drag has no forward signpost — only the band behind them; there is still no edge to the desk, so dragging east of the last column reaches unlabelled nothing; a sheet whose left edge is off the viewport draws no title at all, which is the same defect the band fixes but for the *neighbouring* sheets rather than the one in hand; and the band pops in and out without a fade
- [ ] The pinned band occludes 38px at the top of the canvas, which during a free pan can hide a row of date numerals or slice them mid-glyph. Programmatic framings do not land you there — a Month fit shows the header, so the band is hidden — but free panning can. Either inset every framing by the band height or accept it explicitly; it is the standing cost of a sticky header and it has not been priced
- [x] Fits, jumps and steps glide instead of cutting. `ViewportStore.animate` had been written in five places and read nowhere, so nothing was animated despite the code documenting itself as animated. Two reviewers independently said the cut was the reason the layout stayed invisible: reaching October without ever learning it sits below July and two columns left. Zoom eases geometrically, a gesture abandons a flight in progress, the first framing on load does not fly in from the origin, and `prefers-reduced-motion` turns it off
- [ ] Navigation leftovers from Priya's 2026-09-18 retest: double-clicking a month card in the year view makes a two-pixel note instead of flying into that month, which is what every year view does; "Today" silently changes your zoom, dropping a reader at Week when they were working at Month; the year view has no day numbers and no today marker, which is the one thing a year view is for; there is no horizontal wheel gesture, so the only axis that means "next month" has none; dragging east of the last column reaches unlabelled nothing with no edge marker; and the step shortcuts are advertised only in the arrows' tooltips, not in the command palette that already renders shortcut chips
- [ ] Findings from Marcus's 2026-09-18 keyboard-first retest. The modifier work held — every tool badge told the truth, the Undo tooltip read `Undo Ctrl+Z`, and a Windows power user who complained about everything else never once mentioned a Mac glyph — and he independently confirmed both gaps recorded below: `Ctrl+Y` redoes and is advertised nowhere, and Redo's tooltip names no key despite two working bindings. Undo itself he could not break, which is worth recording so nobody re-investigates: 29 mixed actions undone and redone round-tripped byte-identically, ticks, colours and rotations included, and a recurrence set is one clean step. What he found (the Enter-in-a-title trap is fixed below; the rest stand): `Shift+1` is advertised in the palette as Fit month and does nothing at any zoom, where `⇧T` beside it works. The inspector is a ~264px opaque panel the canvas does not inset for, so a note placed beneath it is invisible and the *next* creation click is swallowed in silence — the typed words then land on the canvas and arm a tool per letter (`e` → Event, `n` → Sticky), which is how one note came to exist where two were intended. A checklist cannot be re-edited once made: double-click, Enter and F2 all leave focus on the body where a text sticky rewrites fine, contradicting the "checklist toggling/editing is done" clause on the first line of this milestone. Undoing something a year away from the viewport says nothing and moves nothing. `Ctrl+A` is still the browser's and blue-highlights the chrome. A repeat cannot end — Never/Daily/Weekly/Monthly/Yearly with no until, count, interval or Tue+Thu — so a 16-week seminar has to be stored as an infinite series. The colour swatches' accessible names are raw token names (`--stationery-yellow`). And on the palette's stale "Today": clicking that row lands on the correct day, so only the *labels* are computed from a three-day-old today, which is also why it calls the 18th "next" Friday
- [x] Enter commits an event title and hands the keyboard back, which is what Tab, click-away and Escape already did. Every editor on the canvas is the same `textarea` — including the event title's one-line box — so Enter's default was to insert a newline the box is not tall enough to show, and focus stayed in a draft that then looked empty because the title had scrolled out of it. Behind `App.onKeyDown`'s `typing` guard that killed every navigation key: PageDown and `Shift+T` did nothing and the application read as frozen, with Enter the one exit that did not exit. The decision is recorded once, on the editor view-model that already discriminates the three editing modes, rather than in the keydown handler: a `singleLine` flag the template passes down, so a fourth editing mode cannot be added without answering the question — it is a compile error, the way deleting the `command` icon made `icon="command"` one. Committing blurs rather than calling `commitEditor`, so all four exits stay one commit path and none of them can drift. The key is compared rather than bound as Angular's `keydown.enter`, which ignores Shift+Enter and would have let a newline back into the one-line box by another route. Where lines are the content — text objects, and checklists that store one item per line — Enter is still a newline
- [x] Every keyboard hint in the app printed ⌘ regardless of platform, on a desktop build whose own dev and demo machine is Windows 11 — `db-kbd` never had a say in it, because the glyph was spelled out at the call sites and the component only echoed what it was handed. Callers now pass the logical `Mod` and the components resolve it through `DB_MODIFIER_CAP`, an injection seam the webview answers synchronously from `navigator.userAgentData?.platform` (falling back to `navigator.platform`); Tauri's `os` plugin was the wrong tool because it answers a promise, and inside an OnPush template that paints ⌘ first and corrects itself a frame after the user has read it. `db-tool-button` takes the same logical spelling and writes it the way each platform does — `⌘Z` against `Ctrl+Z`, since `CtrlZ` reads as one unfamiliar key rather than two familiar ones, and each separator is decided by the cap on its left rather than once for the whole join, which had been dropping the `+` out of every pair the moment the platform was macOS. Two of the ⌘s were not text at all: Lucide's `command` icon drew the loop as a path in the toolbar and again in the palette, 671px from a `Ctrl` keycap that contradicted it — both are a neutral `list` mark now, and `command` is out of the icon registry so the next one is a compile error. The Undo rail badge went with it: the corner is 8.5px of `--ink-muted` in a 32px cell, which survives one letter the eye pattern-matches and not the word "Ctrl" it has to read, so `db-tool-button` now gives the corner to bare keys only and leaves chords to the tooltip
- [ ] The rest of the keycap vocabulary, which is a milder defect than the ⌘ one: `⇧` (`sample-desk.ts:195,204`) and `⎋` (`command-palette.ts:64`) are set verbatim everywhere. Unlike ⌘ these name keys a Windows keyboard *has* — they are merely labelled `Shift` and `Esc` on it — so this is a legibility and idiom problem, not an impossible instruction; the ⎋-reads-as-a-prohibition-sign clause on the chrome line below is the stronger argument for that one. Doing it properly means logical `SHIFT`/`ALT`/`ESC`/`ENTER` tokens through a per-platform keycap map, which replaces `DB_MODIFIER_CAP`'s single string, a joiner that belongs to the platform rather than to `resolveHint`, and macOS's canonical ⌃⌥⇧⌘ ordering. It also retires an encoding that cannot say what it means: caps are separated by `+` in one string, so a literal `+` key reads as a chord — `isSingleCap('+')` is `false` today and such a button would silently lose its corner badge. No caller presses that yet. `Ctrl+Y` belongs in the same pass: it redoes on every platform now but is advertised to nobody, since Redo passes no `shortcut` and the palette has no redo row — and the honest Mac hint for Redo is `⇧⌘Z`, not `⌘Y`, so it needs a per-platform *shortcut* and not just a per-platform cap
- [ ] A tool button's shortcut is absent from the accessibility tree: `.db-tip` is `role="tooltip"` with no `id`, and the button carries only `aria-label`, no `aria-describedby`, so nothing associates the two. Pre-existing, but it costs more now that the corner badge is gone and the tooltip is the rail's only shortcut-teaching surface

## Milestone 6 — First release hardening (delivery step 9)

- [ ] Accessibility: keyboard access to every tool, accessible structured mirrors of canvas content, screen-reader passes
- [ ] Contrast: `--ink-muted` carries caption and metadata text but measures 3.0–4.4:1 on every surface it lands on, in both themes (worst: the 8.5px tool-rail key hint at 3.14:1 on a selected row) — either re-tune the token or move small text to `--ink-secondary`. `.db-input--stateful` is the precedent for the second approach: a placeholder that reports state rather than hinting at a format is content, and takes the readable token
- [ ] Stepper presses each record their own undo step, so five clicks on a number field's arrow need five Ctrl+Z. Defensible under the one-gesture-one-command rule, but coalescing repeated steps on the same field within a short window would match what the rest of the app feels like. Related: `selectedRotation` displays a whole number while the object stores the fractional tilt it was set down with, so an untouched field can read up to half a degree off until the first edit normalises it
- [ ] Inspector follow-ups from the 2026-09-18 design reviews: Position X and Y are world coordinates with no referent a user can read — the origin is never on screen, so "7120 x / 45200 y" names nothing, and dragging is the real gesture for it; the colour picker offers 6 of the 13 stationery colours, so a red event shows no selection and cannot be given its red back once another is picked; the text panel tells you to double-click the desk to rewrite it while a sticky, editable by the identical gesture, says nothing; inspector group headers are `role="button"` with no `tabindex`, so no group collapses from the keyboard; number-field steppers are 14×10 CSS px against the 24×24 WCAG 2.2 asks, with no arrow-key alternative since the input is not `type="number"`; an event that has been dragged off its day cell will carry real geometry once that lands, but `hasGeometry()` only consults `desk.floats()`, so its Geometry group would silently not appear
- [ ] `DbSlider` and the `eye`/`eye-off`/`grip-vertical`/`layers-2` icons have no consumers left after the inspector and layer-panel passes. Keep them as catalogue entries or delete them, but decide — `DbLayerPanel` is recorded as a deliberate keep and these are not. The `command` icon was deleted from the registry in `fb459db` on a different rationale and does not pre-decide this: it had no *permissible* consumer rather than no current one, because it draws the ⌘ loop as a path, which is the defect that commit and `6100a8c` existed to remove. Deleting it makes `icon="command"` a compile error rather than a rule someone has to remember. Unused but valid is still an open question
- [ ] A sticky's `compact` flag is the Pinned argument all over again: `object-view.ts` sizes padding, type and line height from it, `sticky-layout.ts` hit-tests checklists with it, `workspace.ts` sizes the inline editor with it, and `sample-desk.ts` ships `s3` compact — so two sticky sizes sit side by side on the seeded desk with no control anywhere that sets or clears it
- [ ] Findings from Priya's 2026-09-18 smoke test that are not already tracked: selection handles are drawn on all four corners but only the southeast one resizes, so three of the four are decorative and a drag on them does nothing; right-click does nothing anywhere, so there is no Delete, Duplicate or Bring-to-front and the Delete key is the only way to remove anything, unannounced; a checklist selection is titled "Sticky note" and offers no checklist controls, and its colour swatch is not ringed the way a sticky's is; "Jump to date ⌘J" and "⌘ Commands" open the same panel; the year view is twelve blank rectangles with no day numbers and no today marker, which is the one thing a year view is for.
